# sasaru-verbalize-edit

編集の細かい流れだけを書く。絵の中身は書かない。出力は `verbalization.edit` だけである。新しいコマンドは足さない。動画は作らない。

形は `../sasaru/SKILL.md` の「役の形」に従う。ルーターは四つの役を振り、このファイルは振らない。スキーマ、ルーター、テンプレート、他のスキル、設計ノートは変えない。

書く前に `../sasaru-principle-describe-the-form-not-the-work/SKILL.md` と `../sasaru-principle-measure-or-label/SKILL.md` を全文読む。画面の字、せりふ、キャプション、題は、出力に写さない。

## Start

todo を Phase ごとに一つずつ開く。

1. 境界を見る
2. ホールドの長さを数える
3. ズームとトランジションを分ける
4. カットがジャンプを隠すか、新しい段を開くか

渡された動画のうち、ファイルとして開けるものだけを見る。一覧にあってファイルが無いものは、名前を書いて、その本の流れは書かない。

## Phase A: 境界を見る

時間の順に、編集の出来事を一つずつ書く。書くのはカット、ホールド、ズーム、トランジションである。何が映っているか、誰がいるか、何を作っているかは書かない。書いてよいのは、画面が切れたこと、同じ画面が続いたこと、寄ったこと、引いたこと、つなぎの種類である。

見たことは `seen` と書く。フレームの端を指せる秒は見た秒である。指せない読みは `inferred` と書く。見ていない秒は書かない。見た秒と推論を一つの数に混ぜない。このファイルの `seen` は、フレームを指せたという意味である。playbook の `evidence.measured` には入れない。目で読んだ秒を、測った数としてスキーマへ書かない。

## Phase B: ホールド

ホールドは、次のカットまたはトランジションまで、同じ画面が続く区間である。長さは、見た始点から見た終点までの秒である。ホールドごとにその長さを書く。端がフレームで決まらない長さは、推論と書く。

ホールドの途中にズームがあるときは、ホールドの長さと、その中のズームを両方書く。ズームをホールドの長さに畳まない。

## Phase C: ズームとトランジション

ズームは、カットせずに画面が寄る、または引くことである。始点、終点、寄るか引くか、その区間の長さを書く。拡大や縮小をフレームで指せるなら見たことである。倍率を目の印象で置いたら推論である。

トランジションは、一フレームより長いつなぎである。種類は `whip`、`zoom-cut`、`fade`、`match-cut`、`glitch` のどれか、フレームにそれが出ているときだけ書く。種類をフレームで指せるなら見たことである。名前を推測したら推論である。

一フレームで切り替わる境界はカットである。種類は `hard-cut`。トランジションの欄に混ぜない。

## Phase D: カットの仕事

各カットに、次のどちらか一つを書く。両方は書かない。決められないときは、決められないと書き、推測で埋めない。

- ジャンプを隠す。同じ段の途中の時間が飛んでいて、前後の構図は続いている。時間の飛びと構図の続きをフレームで指せるなら、この分類は見たことである。飛ばした理由は書かない。
- 新しい段を開く。前の段の時間飛ばしではなく、次の段の画面が始まる。段が替わったことをフレームで指せるなら、この分類は見たことである。その段が何を意味するかは書かない。

## Outputs

書き込むファイルは `edit.md`。このファイルが `verbalization.edit` である。

中身は次の見出しだけ。この順。動画が複数本なら、`##` を本ごとに繰り返す。呼び名はファイル名から拡張子を取ったものである。

```markdown
# verbalization.edit

## 呼び名

### 出来事
```

`### 出来事` の各行は、秒、種類（`cut`、`hold`、`zoom`、`transition`）、ホールドなら長さ、カットなら「ジャンプを隠す」か「新しい段を開く」か、つなぎならその種類、出どころ（`seen` か `inferred`）。

一覧にあって開けないファイルは、`# verbalization.edit` の直下に名前だけを書く。その本の `##` は作らない。

参照の文は入れない。絵の主題、音、引き、言葉の役割、アカウントの繰り返し、シナリオは書かない。スクリプトもコマンドも足さない。
